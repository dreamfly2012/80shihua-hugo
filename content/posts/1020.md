<p></p>
<p>正则匹配中可以实用一些PCRE修饰符，比如e(eval的意思)，i（ignore-case）下面是官方文档的说明，所以不推荐使用e,可以先行正则匹配，然后使用函数</p>
<p></p>
<ul class=" list-paddingleft-2">
<li>
<p><em class="emphasis" style="text-rendering: optimizeLegibility;">i</em>&nbsp;(<em style="text-rendering: optimizeLegibility;">PCRE_CASELESS</em>)</p>
</li>
<li>
<p><span class="simpara">If this modifier is set, letters in the pattern match both upper and lower case letters.</span></p>
</li>
<li>
<p><em class="emphasis" style="text-rendering: optimizeLegibility;">m</em>&nbsp;(<em style="text-rendering: optimizeLegibility;">PCRE_MULTILINE</em>)</p>
</li>
<li>
<p><span class="simpara">By default, PCRE treats the subject string as consisting of a single &quot;line&quot; of characters (even if it actually contains several newlines). The &quot;start of line&quot; metacharacter (^) matches only at the start of the string, while the &quot;end of line&quot; metacharacter ($) matches only at the end of the string, or before a terminating newline (unless&nbsp;<em class="emphasis" style="text-rendering: optimizeLegibility;">D</em>&nbsp;modifier is set). This is the same as Perl.&nbsp;</span><span class="simpara">When this modifier is set, the &quot;start of line&quot; and &quot;end of line&quot; constructs match immediately following or immediately before any newline in the subject string, respectively, as well as at the very start and end. This is equivalent to Perl&#39;s /m modifier. If there are no &quot;\n&quot; characters in a subject string, or no occurrences of ^ or $ in a pattern, setting this modifier has no effect.</span></p>
</li>
<li>
<p><em class="emphasis" style="text-rendering: optimizeLegibility;">s</em>&nbsp;(<em style="text-rendering: optimizeLegibility;">PCRE_DOTALL</em>)</p>
</li>
<li>
<p><span class="simpara">If this modifier is set, a dot metacharacter in the pattern matches all characters, including newlines. Without it, newlines are excluded. This modifier is equivalent to Perl&#39;s /s modifier. A negative class such as [^a] always matches a newline character, independent of the setting of this modifier.</span></p>
</li>
<li>
<p><em class="emphasis" style="text-rendering: optimizeLegibility;">x</em>&nbsp;(<em style="text-rendering: optimizeLegibility;">PCRE_EXTENDED</em>)</p>
</li>
<li>
<p><span class="simpara">If this modifier is set, whitespace data characters in the pattern are totally ignored except when escaped or inside a character class, and characters between an unescaped # outside a character class and the next newline character, inclusive, are also ignored. This is equivalent to Perl&#39;s /x modifier, and makes it possible to include commentary inside complicated patterns. Note, however, that this applies only to data characters. Whitespace characters may never appear within special character sequences in a pattern, for example within the sequence (?( which introduces a conditional subpattern.</span></p>
</li>
<li>
<p><em class="emphasis" style="text-rendering: optimizeLegibility;">e</em>&nbsp;(<em style="text-rendering: optimizeLegibility;">PREG_REPLACE_EVAL</em>)</p>
</li>
<li>
<div class="warning" style="padding: 0.75rem; margin: 1.5rem 0px; overflow: hidden; border-color: rgb(234, 191, 191); box-shadow: rgba(0, 0, 0, 0.14902) 0px 0px 0px 1px inset; border-radius: 0px 0px 2px 2px; background: rgb(244, 223, 223);"><span class="warning" style="text-rendering: optimizeLegibility; font-weight: bolder; float: left; margin-right: 0.5rem; font-size: 1.125rem;">Warning</span></p>
<p class="simpara" style="margin-top: 0px; margin-bottom: 0px;">This feature was&nbsp;<em class="emphasis" style="text-rendering: optimizeLegibility;">DEPRECATED</em>&nbsp;in PHP 5.5.0, and&nbsp;<em class="emphasis" style="text-rendering: optimizeLegibility;">REMOVED</em>&nbsp;as of PHP 7.0.0.</p>
</div>
<p><span class="simpara">If this deprecated modifier is set,&nbsp;<span class="function"><a href="http://php.net/manual/en/function.preg-replace.php" class="function" style="border-bottom-width: 1px; border-bottom-style: solid; text-decoration: none; color: rgb(51, 102, 153);">preg_replace()</a></span>&nbsp;does normal substitution of backreferences in the replacement string, evaluates it as PHP code, and uses the result for replacing the search string. Single quotes, double quotes, backslashes (<em style="text-rendering: optimizeLegibility;">\</em>) and NULL chars will be escaped by backslashes in substituted backreferences.</span></p>
</li>
</ul>
