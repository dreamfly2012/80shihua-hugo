# 目录覆盖率评估：HTML 标题清洗是否值得做

生成时间：2026-10-18
扫描脚本：`tools/scan_headings.py`（只读，不修改任何文件）
原始数据：`tools/heading_scan_report.json`

## 结论：不做清洗

**没有可清洗的数据。** 全站 859 个 md 文件里，HTML heading 标签几乎不存在：

| 标签 | 全站出现次数 |
|---|---|
| `<h1>` | 6 |
| `<h2>` | 1 |
| `<h3>` | 1 |
| `<h4>`–`<h6>` | 0 |
| `[h2]` 类短代码 | 0 |
| 独占段落的 `<strong>` 伪标题 | 0 |

扫描已排除围栏代码块与 `<pre>` 块，不存在"藏在代码里没扫到"的情况。所以上一轮提到的"把残留 `<h2>` 转成 `##`"是个错误假设——迁移后的正文里根本没有这种残留。

## 目录覆盖率为什么是 21%

842 篇文章中 178 篇有目录，看似偏低，但和篇幅强相关：

| 分组 | 篇数 | 正文字数中位数 | 均值 |
|---|---|---|---|
| 有目录 | 178 | 1284 | 3626 |
| 无目录 | 664 | 582 | 1755 |

绝大多数无目录文章是几百字的随笔，本来就没有（也不需要）章节结构。目录恰好覆盖了最需要它的长文，属于**按需覆盖**，不是漏判。

无目录中仍有 178 篇 ≥1200 字、99 篇 ≥2000 字——这些长文是真的没写小标题，不是格式问题。

## 可选方案对比

| 方案 | 做法 | 评价 |
|---|---|---|
| **A 保持现状** | 什么都不做 | **推荐。** 目录已覆盖长文；JS 兜底逻辑保留，将来写新文章（含 raw HTML 标题）也能自动生成 |
| B AI 补小标题 | 对 ≥2000 字的 99 篇用大模型生成章节标题并插入正文 | 改动正文内容，需逐篇人工审核，存在曲解原意风险，成本高 |
| C 机械分章 | 按段落数均分插入锚点 | 无语义，导航没有意义，不推荐 |

## 附带结论

- `tools/scan_headings.py` 保留，后续若再怀疑有 HTML 标题残留可直接复跑。
- 目录功能本身无需改动：服务端 178 篇直出，其余由 JS 在无足够标题时自动移除侧栏，不留空框。
